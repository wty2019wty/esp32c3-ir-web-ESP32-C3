# 工程结构与实现要点

```text

└── main/
    ├── CMakeLists.txt        # EMBED_TXTFILES 内嵌 index.html
    ├── idf_component.yml     # 依赖 espressif/cjson、espressif/mqtt
    ├── Kconfig.projbuild     # 引脚/载波/WiFi/HTTP/认证/MQTT 配置项
    ├── app_main.c            # 启动顺序：NVS → IR → WiFi → Web → MQTT
    ├── app_ir.c              # RMT RX/TX 核心 + 载波 + RAM 历史
    ├── app_ir_nec.c          # NEC 协议解码
    ├── app_ir_play.c         # hxd/raw 回放编码
    ├── app_ir_store.c        # 帧存储 + 历史环形缓冲 + 多监听器回调（WS/MQTT 共用）
    ├── app_wifi.c            # AP/STA 互斥 + 超时降级
    ├── app_mqtt.c            # MQTT 客户端：命令 RPC + 状态/帧推送 + WiFi 联动
    ├── app_web.c             # HTTP server 初始化（仅静态页面 + WS 端点）
    ├── app_web_api_ir.c      # IR 命令核心（play/carrier/rxpause，WS 共用入口）

    └── include/              # 各模块头文件（app_ir.h / app_wifi.h / app_web.h / app_mqtt.h 等）
```

## 数据流总览

```
VS1838B (GPIO4) → RMT RX (ISR → ir_task) → ir_analyze（NEC 解码 + 波形特征）
    → ir_store_push（最新帧 + 环形历史 + 多监听器回调）
        ├─ WebSocket 推送 frame/status ←→ 浏览器内置页面（cmd RPC 下行）
        └─ MQTT 发布 frame/status      ←→ 外部客户端 / Web-app（ir-web/cmd 下行）

回放：play 命令 → web_rpc_exec → app_ir_play 编码 → RMT TX (GPIO3)
     （期间按开关自动暂停 RX，避免自环帧干扰）
```

- **所有控制与数据走一条 WebSocket**（`/api/ws`），REST API 已移除；
- 命令核心在 `app_web_rpc.c` 的 `web_rpc_exec` 统一分发，MQTT 只是复用同一命令核心的
  另一条传输通道（配置/会话类命令被禁用）。

## sdkconfig.defaults 关键配置

| 配置 | 说明 |
|------|------|
| `CONFIG_IDF_TARGET="esp32c3"` / `FLASHSIZE_4MB` | 目标芯片与 Flash 大小 |
| `FREERTOS_HZ=1000` | 1kHz tick，更细腻的时序 |
| `PARTITION_TABLE_CUSTOM` + `partitions.csv` | nvs + phy_init + factory（约 3.9MB app 区）|
| `NVS_ENCRYPTION` + HMAC 方案（eFuse KEY4） | NVS 加密，首次启动烧写 eFuse 密钥（不可逆）|
| `HTTPD_WS_SUPPORT` + `PRE_HANDSHAKE_CB_SUPPORT` | WebSocket 服务端 + 握手前回调（Origin 白名单必需）|
| `IR_TOOL_MAX_RX_SEGS=1024` / `HISTORY_DEPTH=8` | 每帧最大段数与历史深度（静态 RAM 预算内）|
| `MQTT_PROTOCOL_311/5`、`WS_TRANSPORT`、`MQTT_TRANSPORT_WEBSOCKET(_SECURE)` | MQTT 双协议 + TCP/TLS/WS 传输 |
| `ESP_TLS_SKIP_SERVER_CERT_VERIFY=y` | "跳过校验"模式依赖此回退（默认仍用证书包校验）|

## 实现要点

- **C3 无 RMT DMA**：RX/TX 各用 96 symbols（2×48 内存块），驱动自动 ping-pong；
  单帧上限 96 symbols（NEC 完整帧 34 symbols），长原始数据回放由 copy encoder 分段发送；
  RX 用户缓冲区按 `Max RX segments`（默认 1024）分配，支持超长帧（如空调协议）
- **回放极性**：采集自 VS1838B（active-low）的帧在分析时归一化为"首段载波开"的
  逻辑序列，回放/显示直接复用；RMT TX 只在电平 1 时输出载波。
  极性处理见 `app_ir.c` 的 `ir_analyze` 与 `IR_TOOL_RX_ACTIVE_LOW` 配置：
  active-low 接收头下电平 1 的头部段一律视为引导空闲（无论时长），
  active-high 则仅按时长裁剪
- **载波动态切换**：`rmt_apply_carrier` 无状态限制，回放前可即时重设
- **内存**：历史帧静态环形缓冲（8 帧 × 约 4.2KB ≈ 34KB），不依赖文件系统；
  `ir_task` 栈大小为 `sizeof(ir_frame_t) + 4096`（随 `IR_RAW_MAX_SEGS` 动态调整）
- **RX 缓冲区溢出保护**：ISR 通过 `s_rx_overflow` 标志追踪部分接收事件，
  任务处理前检查符号数量阈值 `num > (IR_RAW_MAX_SEGS + 1) / 2`，
  超出则丢弃帧以避免 `ir_analyze` 截断导致解码错误；
  回放结束恢复 RX 时清除溢出标志
- **Web 数据流**：前端通过单条 WebSocket（`/api/ws`）完成登录、认证、命令与推送，
  **REST API 已移除**。服务器所有帧经 httpd 任务串行发送（入队异步发送 + 每连接队列上限），
  空闲时每 20 秒推送 status 心跳维持连接，前端 45 秒无数据即重连；
  命令与推送均要求已认证会话，登出/改密会立即使已连接会话失效
